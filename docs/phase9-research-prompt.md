I have a C#/MonoGame re-implementation of a Fallout 2 engine slice (**Hexwaste**, tagged v0.8.0) where the opening hour plays armed and the character now comes alive: roll-your-own SPECIAL + tag-3 character creation or a premade picker, skills that grow per level through a spend-allocator, a character sheet, rest-to-heal, merchants that restock. Combat works but is **flat**: turn-based melee + single-shot guns with the engine's to-hit/line-of-fire/ammo math, AP budgets, scripted aggro, ally turns — but **no burst, no aimed shots, no criticals, no knockdown, no throwing, no explosives, and an AI that ignores ai.txt** (flat min_to_hit 30, no distance prefs, no fleeing). The decision is already made for the *direction* — **Combat Depth II** — and for the *discipline*: **extract a testable CombatEngine into `Hexwaste.Formats` FIRST**, as a no-behavior-change refactor that becomes the regression net, before layering crits/ai/burst/throwing on top. What I need researched is the **exact engine fidelity** of each depth feature and an honest M0..M5 plan: the real size of the crit-table port, which ai.txt fields actually move the Den/Klamath fights, the knockback geometry, the throwing/explosive animator rung, and — critically — whether my proposed `ICombatHost`/`ICombatRng` seam matches the current `ViewerGame.cs` turn loop 1:1 so M0 can be proven behavior-preserving.

## Directions to research

1. **M0 — the CombatEngine seam (the load-bearing question).** Audit `ViewerGame.cs` (`CombatPhase` ~:100, `UpdateCombat` ~:639, `StepEnemyTurn`, `TryEnemyAction`/`TryAllyAction`/`EnemyAttack`, `RollAttack`/`ResolveAttack`/`KillCritter`) and define the **exact** `ICombatHost` callback set + `ICombatRng` interface that lets the whole turn machine move into `Hexwaste.Formats.Combat.CombatEngine` with **zero behavior change**. Specifically confirm: (a) the "animation-busy = turn clock" coupling reduces cleanly to an `IsAnimationBusy` host signal; (b) every draw-list / `_blockedTiles` mutation (corpse conversion, NPC walk `TileChanged`) routes through a host callback so corpses don't go invisible/mis-sorted; (c) **all three** `_dudeAp` reset points are reproduced; (d) `MapObject` stays the single mutable source of truth (it's a dict/HashSet key everywhere — don't split ownership). Deliver the interface in C#-ish pseudocode and a list of the exact `Console.WriteLine` lines that must survive verbatim for the transcript tests.
2. **AI packets / ai.txt** — parse `data\ai.txt` (INI; ~what size, which sections matter for the slice?) and consume the already-parsed-but-unused `MapObject.AiPacket`. Which fields actually move the Den/Klamath fights? Port the real logic, citing `combat_ai.cc`: `min_to_hit` (walk tile-by-tile until toHit ≥ min, else flee — vs our flat 30), `min_hp` flee (the RAW hp threshold, NOT the run_away_mode % table — confirm which the AI packet uses), `_cai_perform_distance_prefs` (stay/charge/snipe/on-your-own). Name the line ranges. Which packets do the actual Den NPCs (denbus*) carry?
3. **Knockdown / knockback** — `KnockedDown` flag on `CritterState` + an additive-V2 save delta. Port the geometry from `combat.cc`: when does knockback fire (explosion / unarmed / melee only?), distance = dmg/10 shove along a straight hex line, the get-up anims (36/37) and their AP cost (3, or 1 with Quick Recovery), and the +40-to-hit-vs-prone modifier. Cite line ranges (knockback ~4634-4659, +40 ~4475). Is knockback blocked by occupied tiles?
4. **Aimed shots + criticals — the table reality check.** Count the rows: how big is the per-bodypart critical-effect table port REALLY (`combat.cc` ~189-1790)? Recommend the **minimal** honest cut: transcribe the full table (checksum-verify the port against the source) but honor only {damageMultiplier, KNOCKED_DOWN, DEAD, BYPASS-armor}, masking cripple/blind/knockout/lose-turn for now. Throwing reuses the ranged to-hit math + **one new animator mode**: move-object-along-a-straight-hex-line (the projectile is the weapon object, recoverable). Size that mode (~60-80 LoC?).
